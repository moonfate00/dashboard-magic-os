# P6 Five-Cabin Intake Foundation Acceptance

## Accepted slice

This slice adds one review-first intake runtime shared by Command, Assets, Social, Navigation, and Memory.

- An immutable session state machine preserves source material, human type and preset locks, assistant proposals, candidate selection, and verification state.
- One adapter registry owns the five cabin intake boundaries.
- The Assets adapter classifies image, video, audio, PDF, archive, link, and document inputs without merging different media into one formal object.
- The Navigation adapter recognizes a three-level learning contract: P1 root, P2 branch, and P3 card. Deeper Markdown headings are flattened into P3 and never create P4.
- Each P3 card has one primary P2 and may later attach to multiple related P2 nodes.
- Existing P2 titles can be matched to an injected P1/P2 catalog without guessing Vault paths.
- The public service entry exposes an in-memory runtime only. It performs no Vault write and grants no AI provider authority.

## Installed-runtime evidence

The private installed edition consumes the same contracts through its compatibility foundation. Its unified classification workbench exposes five inspector tabs, including the Navigation hierarchy inspector. The live Obsidian check confirmed the existing `公文` P1 with six P2 branches; final execution was deliberately not triggered during the synthetic test.

## Safety boundary

- Source material and candidate sessions remain in memory until an explicit host workflow saves a draft or confirms execution.
- Adapters return stable warning codes rather than localized interface strings.
- User records, absolute paths, AI credentials, jobs, and management logs are not part of this public extraction.
- A host must still route every future write through preview, confirmation, journal, rollback, and post-write verification.

## Automated evidence

- Five-cabin adapter coverage and immutable session transitions.
- Asset media classification and mixed-input separation.
- P1/P2 matching, P3 extraction, and no-P4 enforcement.
- Public service exposure without Vault capabilities.
- Full test, i18n, privacy, build, release, and package audits.
