# Security Policy

## Supported versions

Only the newest published alpha or stable release receives security fixes.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose vault data, health information, credentials, entitlement material, or filesystem paths.

Until a public repository security-advisory URL is configured, do not publish exploit details. The public GitHub repository must enable **Security advisories** before the first external test release; reports should then use **Security → Report a vulnerability**.

Include the affected version, reproduction steps using synthetic data, impact, and any suggested mitigation. Never attach a real vault, `data.json`, API key, signed entitlement, or private record.
